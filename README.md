# 微信发送

一款纯本机运行的 macOS 微信定时发送工具。它可以创建单次、每天或每周任务，在指定时间通过当前 Mac 上已登录的微信发送文字和本机文件，也支持随时“立即执行”。

程序不部署服务器，不读取或解密微信数据库，不扫描微信账号目录，不上传联系人、消息、附件或执行记录，也不需要屏幕录制权限。

> [!IMPORTANT]
> 这是第三方 UI 自动化工具，并非微信官方产品。微信搜索会直接打开第一项，因此联系人名称必须唯一。建议先给目标联系人设置唯一备注名，并用“文件传输助手”和安全预览完成验证。

## 主要功能

- 单次、每天和每周发送任务
- 文字消息与多个本机附件
- SwiftUI 主窗口和菜单栏入口
- 默认安全预览：只把内容填入聊天框，不按发送键
- 显式的真实发送总开关
- 创建和编辑任务时强制确认联系人名称唯一
- 微信进程与“编辑 → 搜索”菜单可用性检查
- 本地 JSON 原子持久化，保留最近 200 条执行记录
- 可选 LaunchAgent 登录后常驻
- 计划时间错过超过两分钟时停止，不静默补发
- “立即执行”与原定时计划相互独立，不会提前消耗或破坏计划状态

## 执行流程

```text
任务到期或用户点击“立即执行”
  → 校验联系人、内容、附件和唯一性确认
  → 记录执行前正在使用的应用
  → 激活已登录的微信
  → 通过辅助功能打开“编辑 → 搜索”
  → 通过 WindowServer 元数据找到微信独立搜索面板并点击其搜索框
  → 使用 CGEvent 逐字输入联系人
  → 等待微信刷新搜索结果
  → 直接按 Enter 打开第一项
  → 粘贴文字和/或文件
  → 安全预览停在草稿，或在真实发送模式下按 Enter
  → 恢复执行前正在使用的应用
  → 写入执行记录；只有定时执行才推进计划状态
```

程序不通过截图、OCR 或微信数据库判断重名。联系人唯一性由创建任务时的确认承担。如果搜索结果可能重名，请先在微信中设置仅属于目标联系人的备注名，再把该备注名填入任务。

## 实现原理

### 1. 任务创建与持久化

任务包含联系人、文字、附件路径、执行时间、重复规则和“联系人唯一”确认。`TaskStore` 使用 `Codable` 将状态写到 `~/Library/Application Support/WeChatSend/state.json`，并通过原子写入避免保存中断留下不完整 JSON。所有数据只保存在当前 Mac。

### 2. 到点调度与立即执行隔离

`TaskScheduler` 在主运行循环的 `.common` 模式中每 5 秒查询一次到期任务，同一时间只允许一个自动化流程执行。定时执行会把任务切换到运行状态，并在成功后结束单次任务或计算下一次重复时间；失败时保留错误状态供用户重试。

“立即执行”只新增一条执行记录，不修改任务原有的 `pending`、启用状态或计划时间。因此，即使在到点前几秒手动运行失败，原定时任务仍会在到点后独立触发。若 Mac 睡眠或应用未运行导致任务晚到超过 120 秒，任务会进入“需要确认”，不会在用户不知情时补发。

### 3. 微信状态检查

`WeChatStatusMonitor` 每 15 秒在主线程通过 `NSWorkspace` 检查微信主进程，并在已有辅助功能权限时只读检查“编辑 → 搜索”菜单是否可用。执行时会在主线程通过 Launch Services 真正激活微信；随后用 Accessibility 提升微信主窗口，避免 `NSRunningApplication.activate()` 返回成功但前台仍停留在其他应用。最后通过 `CGWindowListCopyWindowInfo` 只读取微信搜索浮窗的 PID、层级和边界，不读取窗口图像或文字。它不打开微信数据目录，不读取 `wxid`、联系人表或聊天数据库。界面中的微信名或微信号由用户自行填写，仅作为本机状态标注。

### 4. 打开搜索并输入联系人

程序先记录当前前台应用，再在主线程通过 Launch Services 激活微信，并提升其主窗口，确保当前菜单属于微信而不是原先的应用。随后通过 Accessibility API 遍历菜单栏并触发“编辑 → 搜索”。微信 4.x 的搜索控件并不总是暴露在可访问性树中，因此程序等待微信主进程创建独立搜索浮窗，通过 WindowServer 元数据确认浮窗存在，然后点击浮窗顶部的搜索框取得焦点。程序清空搜索框后，使用 `CGEvent` 按 Unicode 字符逐字输入联系人。

输入完成后程序等待搜索结果稳定，再按用户已经确认的唯一名称直接按 Enter 打开第一项。程序会在 Enter 后确认独立搜索面板已经关闭，只有确认进入下一步才会粘贴消息。整个过程不截图、不做 OCR、不读取窗口内容，也不把联系人名称放入剪贴板。

### 5. 消息与附件发送

进入聊天后，文字通过系统剪贴板粘贴，附件以本机文件 URL 数组写入 `NSPasteboard` 后粘贴。安全预览模式不会按发送键；真实发送模式才会通过 `CGEvent` 提交 Enter。程序记录的是“已向微信投递发送按键”，无法代表微信服务器已发送成功、对方已接收或已读。

### 6. 前台恢复

微信 UI 自动化仍要求微信短暂成为前台，但程序不再隐藏或关闭“微信发送”窗口。执行结束后会恢复执行前的应用：手动运行通常回到“微信发送”，后台定时运行则回到用户当时正在使用的应用。

### 7. 权限与常驻

程序只需要 macOS“辅助功能”权限，用于读取微信菜单并投递键盘事件；不需要屏幕录制权限，也不请求访问其他 App 的数据。macOS 不允许应用自行绕过 TCC 静默授权，首次使用仍需用户手动允许一次。应用使用固定 Bundle ID 和稳定指定要求签名，使本机覆盖安装后的版本继续匹配已有授权。

启用“登录后保持运行”时，程序写入用户级 LaunchAgent。安装脚本在更新应用前先卸载代理、替换应用，再重新加载，避免旧进程在安装时抢先重启。

## 系统要求

- macOS 14 或更高版本
- 已安装并登录 macOS 微信客户端
- Mac 在执行时保持唤醒和解锁
- 已为“微信发送”授予一次辅助功能权限

## 下载与安装

从 [Releases](https://github.com/Xiangcainoeat/wechat-send-macos/releases) 下载 `WeChatSend-v1.0.4-macOS.zip`，解压后把“微信发送.app”移动到“应用程序”。

当前公开压缩包使用 ad-hoc 签名，没有 Apple Developer ID 公证。首次打开若被 Gatekeeper 阻止，请在“系统设置 → 隐私与安全性”中核对应用来源后选择“仍要打开”。不信任预编译文件时，请按下一节从源码构建。

## 从源码构建

```bash
git clone git@github.com:Xiangcainoeat/wechat-send-macos.git
cd wechat-send-macos
chmod +x scripts/build-app.sh scripts/install-app.sh
./scripts/build-app.sh
```

构建脚本会先运行完整测试，再生成 `dist/微信发送.app`。

构建并同步安装到 `/Applications`：

```bash
./scripts/install-app.sh
```

`install-app.sh` 会统一更新 `dist` 和“应用程序”中的副本；若已启用 LaunchAgent，会在替换应用前安全卸载，并在完成后重新加载。

## 首次使用

1. 打开“微信发送”，在“设置”中授予辅助功能权限。
2. 保持微信登录、Mac 唤醒并解锁。
3. 新建接收人为“文件传输助手”的任务，勾选联系人唯一确认。
4. 保持“允许真实发送”关闭，运行任务并确认程序进入正确聊天、只填入草稿。
5. 验证无误后，再按需开启真实发送。

## 数据与隐私

- 任务、设置和日志只写入当前用户的 Application Support 目录。
- 程序不连接自建服务器，不监听网络端口，不上传任务内容。
- 程序不读取或解密微信数据库，不扫描微信容器，不需要数据库密钥。
- 程序不截取屏幕，不保存界面图像，不需要屏幕录制权限。
- 附件仅在任务执行时通过系统剪贴板交给本机微信。

## 已知限制

- UI 自动化依赖微信菜单结构；微信升级后应先重新执行安全预览。
- 联系人必须唯一；程序会直接打开搜索第一项，无法自行判断两个同名联系人。
- 执行时微信会短暂成为前台；期间切换窗口或输入键盘可能使任务失败。
- 应用不会解锁 Mac，也不会唤醒已经睡眠的机器。
- “已提交发送”不是送达回执，请在微信中检查最终结果。
