# 微信发送

一款纯本机运行的 macOS 微信定时发送工具。你可以临时创建单次、每天或每周任务，在指定时间向唯一联系人发送文字和本机文件。执行前会通过微信截图层和本地 OCR 核对搜索框与唯一结果，验证失败时不会进入聊天或发送内容。

微信发送只控制当前 Mac 上已经登录的微信客户端：不读取或解密微信数据库，不需要数据库密钥，不上传联系人、消息、附件或执行记录，也不需要部署服务器。

> [!IMPORTANT]
> 这是第三方 UI 自动化工具，并非微信官方产品。请先用“文件传输助手”和安全预览完成验证，再开启真实发送。

## 主要功能

- 单次、每天和每周发送任务
- 文字消息与多个本机附件
- SwiftUI 主窗口和菜单栏入口
- 默认安全预览：只把内容填入聊天框，不按发送键
- 真实发送总开关，避免新任务直接发送
- 联系人唯一性双重保护：创建时强制确认，执行时截图复核
- 微信运行状态与本机 `wxid` 目录标识检查
- 本地 JSON 原子持久化，保留最近 200 条执行记录
- 可选 LaunchAgent 登录后常驻
- 计划时间错过超过两分钟时停止执行，不静默补发

## 执行流程

```text
任务到期
  → 校验联系人、内容、附件和唯一性确认
  → 激活已登录的微信
  → 通过辅助功能打开“编辑 → 搜索”
  → 使用 CGEvent 逐字输入联系人，等待微信刷新搜索结果
  → 触发微信 Control-Command-K 截图层
  → 通过 ScreenCaptureKit 在内存中截取搜索面板
  → 使用 Vision OCR 核对搜索框和可聊天结果分区
  → 仅在精确匹配结果为一个时按 Enter
  → 粘贴文字和/或文件
  → 安全预览停在草稿，或在真实发送模式下按 Enter
  → 写入任务状态和执行记录
```

联系人必须唯一。程序只统计“联系人”“群聊”“功能”“公众号”等可进入聊天的结果分区，网络搜索建议和“聊天记录”中的同名文字不会被算作联系人。精确匹配为零个或多个时会安全停止；仍建议给重名联系人设置唯一备注名，并在任务中确认名称唯一。

## 实现原理

### 1. 任务创建与持久化

任务包含联系人、文字、附件路径、执行时间、重复规则和“联系人唯一”确认。`TaskStore` 使用 `Codable` 将状态写到 `~/Library/Application Support/WeChatSend/state.json`，并通过原子写入避免保存中断留下半个 JSON 文件。所有数据只保存在当前 Mac。

### 2. 到点调度与过期保护

`TaskScheduler` 使用主运行循环中的 `Timer` 每 5 秒查询一次到期任务，同一时间只允许一个任务执行。定时任务和“立即执行”使用同一个自动化入口，完成后都会恢复“微信发送”窗口。若 Mac 睡眠或应用未运行导致任务晚到超过 120 秒，任务会进入“需要确认”，不会在用户不知情时补发。每天和每周任务在成功提交或生成预览草稿后计算下一次时间。

### 3. 微信状态识别

`WeChatStatusMonitor` 每 15 秒通过 `NSWorkspace` 检查微信进程。登录账号只通过微信容器中的 `all_users/login/wxid_*` 目录名称被动推断，也允许用户自行填写显示名称；程序不打开聊天数据库，不读取联系人表，也不持有微信凭据。

### 4. 打开搜索并输入联系人

程序先激活微信，再通过 Accessibility API 遍历菜单栏并触发“编辑 → 搜索”。微信 4.x 的搜索控件不总是出现在可访问性树中，而且一次性粘贴文字可能只改变显示内容、不触发结果刷新。因此程序清空当前搜索框后，用进程定向 `CGEvent` 按 Unicode 字符逐字输入联系人。此操作会触发微信自身的搜索更新，不依赖数据库、坐标点击或剪贴板中的联系人文本。

### 5. 截图与唯一结果验证

微信窗口的直接窗口级截图可能返回黑屏。程序改为在微信前台时触发其全局 `Control-Command-K` 截图工具，让微信先生成可见的合成截图层，再通过 `ScreenCaptureKit` 捕获显示器并按微信主窗口边界裁剪搜索面板。截图只存在于进程内存，识别结束后立即释放，不写入磁盘或上传。

Vision OCR 分三步验证：先从搜索框小区域精确回读输入值；再识别搜索面板中的分区标题；最后从去除头像图标的文字列中统计精确联系人名称。只有“联系人”“群聊”“功能”“公众号”“企业微信联系人”等可聊天分区内恰好出现一个精确匹配时才通过，网络建议和聊天记录被排除。通过后程序才向搜索框发送 Enter；零结果、重名、分区识别失败或截图被其他窗口遮挡都会在选择联系人前停止。

截图期间程序会把鼠标暂时停放在结果区外，捕获完成后使用微信支持的右键手势退出截图层，并把鼠标恢复到原位置。程序还会确认全屏截图层确实关闭；未关闭时不会继续执行。

### 6. 消息与附件发送

联系人进入聊天后，文字通过系统剪贴板粘贴，附件则以本机文件 URL 数组写入 `NSPasteboard` 后粘贴。安全预览模式不会按发送键；真实发送模式才会通过 `CGEvent` 提交 Enter。程序记录的是“已向微信提交按键”，无法代表微信服务器已发送成功、对方已接收或已读。

### 7. 权限与常驻

Accessibility API 和进程定向键盘事件需要 macOS“辅助功能”权限，`ScreenCaptureKit` 需要“屏幕录制”权限。应用使用固定 Bundle ID 和稳定的指定要求签名，使覆盖安装后的本机版本尽量沿用既有授权。启用“登录后保持运行”时，程序写入用户级 LaunchAgent，并由安装脚本在更新应用前先卸载、替换后再加载，避免常驻进程抢先启动旧版本。

## 系统要求

- macOS 14 或更高版本
- 已安装并登录 macOS 微信客户端
- Mac 在执行时保持唤醒和解锁
- 已为“微信发送”授予辅助功能和屏幕录制权限
- 微信截图快捷键保持为 `Control-Command-K`

## 下载与安装

从 [Releases](https://github.com/Xiangcainoeat/wechat-send-macos/releases) 下载 `WeChatSend-v1.0.2-macOS.zip`，解压后把“微信发送.app”移动到“应用程序”。

当前公开压缩包使用 ad-hoc 签名，没有 Apple Developer ID 公证。首次打开若被 Gatekeeper 阻止，请在“系统设置 → 隐私与安全性”中核对应用来源后选择“仍要打开”。不信任预编译文件时，请按下一节从源码构建。

## 从源码构建

```bash
git clone git@github.com:Xiangcainoeat/wechat-send-macos.git
cd wechat-send-macos
chmod +x scripts/build-app.sh scripts/install-app.sh
./scripts/build-app.sh
```

构建脚本会先运行完整测试，再生成 `dist/微信发送.app`。

构建并同步安装到 `/Applications`：

```bash
./scripts/install-app.sh
```

`install-app.sh` 会统一更新 `dist` 和“应用程序”中的副本；若已启用 LaunchAgent，会在替换应用前安全卸载，并在完成后重新加载。

## 首次使用

1. 打开“微信发送”，在“设置”中授予辅助功能和屏幕录制权限；首次授权后重新打开应用。
2. 保持微信登录、Mac 解锁，并确认微信截图快捷键为 `Control-Command-K`。
3. 新建接收人为“文件传输助手”的任务，勾选联系人唯一确认。
4. 保持“允许真实发送”关闭，运行任务并确认程序进入正确聊天、只填入草稿。
5. 验证无误后，再按需开启真实发送。

## 数据与隐私

- 任务、设置和日志只写入当前用户的 Application Support 目录。
- 程序不连接自建服务器，不监听网络端口，不上传任务内容。
- 程序不读取或解密微信数据库，不需要数据库密钥。
- 每次执行会短暂截取微信搜索面板，并使用 Apple Vision 在本机内存中 OCR；图像不会落盘或上传。
- 附件仅在任务执行时通过系统剪贴板交给本机微信。

## 已知限制

- UI 自动化依赖微信菜单结构；微信升级后应先重新执行安全预览。
- 搜索结果必须唯一；发现同名结果时会停止，请先设置唯一备注名。
- 执行依赖微信截图快捷键 `Control-Command-K`；修改该快捷键后任务会安全失败。
- 执行时微信和截图层会短暂成为前台，鼠标会被暂时停放后恢复；期间切换窗口、移动鼠标或输入键盘可能使验证失败。
- 应用不会解锁 Mac，也不会唤醒已经睡眠的机器。
- “已提交发送”不是送达回执；请在微信中检查最终结果。
