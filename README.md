# 微信发送

一款纯本机运行的 macOS 微信定时发送工具。你可以临时创建单次、每天或每周任务，在指定时间向唯一联系人发送文字和本机文件。

微信发送只控制当前 Mac 上已经登录的微信客户端：不读取或解密微信数据库，不需要数据库密钥，不上传联系人、消息、附件或执行记录，也不需要部署服务器。

> [!IMPORTANT]
> 这是第三方 UI 自动化工具，并非微信官方产品。请先用“文件传输助手”和安全预览完成验证，再开启真实发送。

## 主要功能

- 单次、每天和每周发送任务
- 文字消息与多个本机附件
- SwiftUI 主窗口和菜单栏入口
- 默认安全预览：只把内容填入聊天框，不按发送键
- 真实发送总开关，避免新任务直接发送
- 联系人唯一性强制确认，未确认的任务拒绝执行
- 微信运行状态与本机 `wxid` 目录标识检查
- 本地 JSON 原子持久化，保留最近 200 条执行记录
- 可选 LaunchAgent 登录后常驻
- 计划时间错过超过两分钟时停止执行，不静默补发

## 执行流程

```text
任务到期
  → 校验联系人、内容、附件和唯一性确认
  → 激活已登录的微信
  → 通过辅助功能打开“编辑 → 搜索”
  → 定位微信的 AXSearchField
  → 通过 AXValue 写入并回读联系人名称
  → 等待搜索结果后通过 AXConfirm 选择第一项
  → 粘贴文字和/或文件
  → 安全预览停在草稿，或在真实发送模式下按 Enter
  → 写入任务状态和执行记录
```

搜索面板打开后，程序不会截图或 OCR，也不会再次尝试识别界面。联系人必须唯一：请给重名联系人设置唯一备注名，并在任务中确认搜索名称只对应一个结果。程序会直接选择搜索结果第一项，无法替你判断重名。

## 技术栈

| 层级 | 技术 | 用途 |
| --- | --- | --- |
| 语言与构建 | Swift 5.10、Swift Package Manager | 应用、测试和 Release 构建 |
| 桌面界面 | SwiftUI、AppKit | 主窗口、菜单栏、文件选择与应用生命周期 |
| UI 自动化 | macOS Accessibility API、`AXUIElement`、`AXValue`、`AXConfirm` | 打开搜索、验证联系人已写入并确认首项 |
| 键盘输入 | Core Graphics、`CGEvent` | 向微信进程发送消息粘贴、发送 Enter 和清理草稿等按键 |
| 内容传递 | `NSPasteboard` | 向微信输入文字和本机文件 URL |
| 应用与账号状态 | `NSWorkspace`、Foundation 文件 API | 检查微信进程，并被动发现本机 `wxid` 目录标识 |
| 本地调度 | Foundation `Timer`、Swift Concurrency | 每 5 秒检查到期任务并串行执行 |
| 数据保存 | `Codable`、JSON、原子写入 | 保存任务、设置和最近 200 条执行记录 |
| 后台常驻 | macOS LaunchAgent | 登录后启动并保持调度器运行 |
| 质量保障 | Swift Testing、zsh 构建脚本 | 模型、生命周期、发布版本和自动化顺序回归测试 |

## 实现原理

### 1. 任务创建与持久化

任务包含联系人、文字、附件路径、执行时间、重复规则和“联系人唯一”确认。`TaskStore` 使用 `Codable` 将状态写到 `~/Library/Application Support/WeChatSend/state.json`，并通过原子写入避免保存中断留下半个 JSON 文件。所有数据只保存在当前 Mac。

### 2. 到点调度与过期保护

`TaskScheduler` 使用主运行循环中的 `Timer` 每 5 秒查询一次到期任务，同一时间只允许一个任务执行。定时任务和“立即执行”使用同一个自动化入口，完成后都会恢复“微信发送”窗口。若 Mac 睡眠或应用未运行导致任务晚到超过 120 秒，任务会进入“需要确认”，不会在用户不知情时补发。每天和每周任务在成功提交或生成预览草稿后计算下一次时间。

### 3. 微信状态识别

`WeChatStatusMonitor` 每 15 秒通过 `NSWorkspace` 检查微信进程。登录账号只通过微信容器中的 `all_users/login/wxid_*` 目录名称被动推断，也允许用户自行填写显示名称；程序不打开聊天数据库，不读取联系人表，也不持有微信凭据。

### 4. 打开搜索并选择联系人

程序先激活微信，再通过 Accessibility API 遍历菜单栏并触发“编辑 → 搜索”。微信的独立搜索框在后台触发时可能没有键盘焦点，因此程序不再依赖盲发 `Command+V`：它会定位子角色为 `AXSearchField` 或标识为 `_SC_SEARCH_FIELD` 的控件，通过 `AXValue` 直接写入联系人，并回读确认值完全一致。只有验证成功后，才调用该搜索框支持的 `AXConfirm` 动作；这相当于在搜索框中按 Enter 选择第一项。

这一机制既避免了截图导致微信搜索界面退出，也避免了定时执行时搜索框无焦点却被误记为已输入。若找不到可写搜索框、写入失败、回读不一致或控件不支持确认，程序会在选择联系人和发送消息之前安全停止。程序仍无法判断结果是否重名，因此每个任务都必须由用户确认联系人名称唯一。

### 5. 消息与附件发送

联系人进入聊天后，文字通过系统剪贴板粘贴，附件则以本机文件 URL 数组写入 `NSPasteboard` 后粘贴。安全预览模式不会按发送键；真实发送模式才会通过 `CGEvent` 提交 Enter。程序记录的是“已向微信提交按键”，无法代表微信服务器已发送成功、对方已接收或已读。

### 6. 权限与常驻

Accessibility API 和进程定向键盘事件需要 macOS“辅助功能”权限。应用使用固定 Bundle ID 和稳定的指定要求签名，使覆盖安装后的本机版本尽量沿用既有授权。启用“登录后保持运行”时，程序写入用户级 LaunchAgent，并由安装脚本在更新应用前先卸载、替换后再加载，避免常驻进程抢先启动旧版本。

## 系统要求

- macOS 14 或更高版本
- 已安装并登录 macOS 微信客户端
- Mac 在执行时保持唤醒和解锁
- 已为“微信发送”授予辅助功能权限

## 下载与安装

从 [Releases](https://github.com/Xiangcainoeat/wechat-send-macos/releases) 下载 `WeChatSend-v1.0.1-macOS.zip`，解压后把“微信发送.app”移动到“应用程序”。

当前公开压缩包使用 ad-hoc 签名，没有 Apple Developer ID 公证。首次打开若被 Gatekeeper 阻止，请在“系统设置 → 隐私与安全性”中核对应用来源后选择“仍要打开”。不信任预编译文件时，请按下一节从源码构建。

## 从源码构建

```bash
git clone git@github.com:Xiangcainoeat/wechat-send-macos.git
cd wechat-send-macos
chmod +x scripts/build-app.sh scripts/install-app.sh
./scripts/build-app.sh
```

构建脚本会先运行完整测试，再生成 `dist/微信发送.app`。

构建并同步安装到 `/Applications`：

```bash
./scripts/install-app.sh
```

`install-app.sh` 会统一更新 `dist` 和“应用程序”中的副本；若已启用 LaunchAgent，会在替换应用前安全卸载，并在完成后重新加载。

## 首次使用

1. 打开“微信发送”，在“设置”中授予辅助功能权限；本流程不需要屏幕录制权限。
2. 保持微信登录、Mac 解锁。
3. 新建接收人为“文件传输助手”的任务，勾选联系人唯一确认。
4. 保持“允许真实发送”关闭，运行任务并确认程序进入正确聊天、只填入草稿。
5. 验证无误后，再按需开启真实发送。

## 数据与隐私

- 任务、设置和日志只写入当前用户的 Application Support 目录。
- 程序不连接自建服务器，不监听网络端口，不上传任务内容。
- 程序不读取或解密微信数据库，不需要数据库密钥。
- 程序不截图、不进行 OCR，不采集聊天窗口内容。
- 附件仅在任务执行时通过系统剪贴板交给本机微信。

## 已知限制

- UI 自动化依赖微信菜单结构；微信升级后应先重新执行安全预览。
- 搜索结果必须唯一。重名时可能进入错误聊天，请先设置唯一备注名。
- 执行时微信会短暂成为前台应用，期间切换窗口或输入键盘可能干扰流程。
- 应用不会解锁 Mac，也不会唤醒已经睡眠的机器。
- “已提交发送”不是送达回执；请在微信中检查最终结果。
